# Smoke Tests

Persistent, dependency-free Node scripts verifying specific behavior fixes in codex-kit. Each file targets one component and exits `0` on all-pass, `1` on any failure — no test framework required.

Run from `plugins/codex-kit/`:

```bash
node scripts/smoke-tests/commands-arg-handling.mjs
node scripts/smoke-tests/codex-review-bridge-trust-boundary.mjs
node scripts/smoke-tests/codex-review-bridge-semantic-validation.mjs
node scripts/smoke-tests/codex-exec-schema-validation.mjs
node scripts/smoke-tests/codex-exec-secret-redaction.mjs
node scripts/smoke-tests/codex-exec-windows-spawn.mjs
node scripts/smoke-tests/broker-rpc-auth.mjs
node scripts/smoke-tests/codex-rescue-prompt-assembly.mjs
node scripts/smoke-tests/codex-verify-prompt-assembly.mjs
node scripts/smoke-tests/codex-research-prompt-assembly.mjs
node scripts/smoke-tests/stop-review-gate-hook.mjs
node scripts/smoke-tests/codex-config-toml-sections.mjs
node scripts/smoke-tests/session-lifecycle-hook.mjs
node scripts/smoke-tests/fs-atomic-write.mjs
node scripts/smoke-tests/codex-windows-guardrails-preflight.mjs
node scripts/smoke-tests/codex-audit-loop-invariants.mjs
node scripts/smoke-tests/codex-peer-review-invariants.mjs
node scripts/smoke-tests/codex-plan-loop-invariants.mjs
node scripts/smoke-tests/codex-prompt-protocol-references.mjs
node scripts/smoke-tests/codex-session-lookup-scripts.mjs
node scripts/smoke-tests/plugin-marketplace-review-references.mjs
node scripts/smoke-tests/git-untracked-secret-screen.mjs
```

Or all at once:

```bash
for f in scripts/smoke-tests/*.mjs; do node "$f" || echo "FAILED: $f"; done
```

## What each one covers

| File | Component | What it verifies |
|---|---|---|
| `commands-arg-handling.mjs` | `commands/status.md`, `result.md`, `transfer.md`, `cancel.md`, `review.md`, `adversarial-review.md` | The underlying `codex-companion.mjs` subcommands still work when invoked as separate, individually-quoted arguments (the pattern these commands now instruct the model to use, instead of interpolating a raw `$ARGUMENTS` blob). The `review`/`adversarial-review` cases use a deliberately-invalid `--scope` value so the check exercises real argument parsing while failing fast, before ever reaching Codex — these two never spawn a real review. |
| `stop-review-gate-hook.mjs` | `hooks/hooks.json`'s Stop hook (`scripts/stop-review-gate-hook.mjs`) | The hook's exported `parseStopReviewOutput`/`buildStopReviewPrompt` functions directly: ALLOW/BLOCK/malformed-output decision logic, and that the previous turn's assistant message lands inside its own delimited `<claude_response_evidence>` block (not `<task>`) with explicit trust-boundary framing text present. |
| `codex-review-bridge-trust-boundary.mjs` | `skills/codex-review-bridge/scripts/bridge-invoke.mjs` | The containment check rejects an `--instruction-file` that resolves inside `--target-paths` (the self-referential-reviewer-instructions case), and does not false-positive on a legitimately trusted, outside-scope instruction file. Also: `CODEX_KIT_REVIEW_MODEL` and `CODEX_KIT_REVIEW_TIMEOUT_MS` env-var validation both fail fast on a malformed value before any Codex call. |
| `codex-review-bridge-semantic-validation.mjs` | `skills/codex-review-bridge/scripts/bridge-invoke.mjs` | `semanticallyValidate`'s optional `components[]` finding field: a valid entry passes, an out-of-scope or nonexistent entry is rejected with a components-specific error message, omitting `components[]` entirely stays backward compatible, and the pre-fix workaround (a multi-path string crammed into `location` alone) is still correctly rejected — proving the fix adds a field rather than loosening the existing `location` check. |
| `codex-exec-schema-validation.mjs` | `scripts/lib/codex-exec.mjs` | `findSchemaViolation`'s union-type (`type: [...]`) support, added after a real CI regression where a nullable field (`type: ["array", "null"]`, required by OpenAI's strict structured-output mode) silently skipped local validation: `null` and a valid array both pass, a wrong-shaped array or a non-array/non-null value are rejected, and pre-existing bare-string-type behavior is unchanged. |
| `codex-exec-secret-redaction.mjs` (14 assertions) | `scripts/lib/codex-exec.mjs` | `redactSecrets` directly: known secret-shaped patterns are redacted from a raw stderr tail before it lands in a typed-failure `detail`; plain diagnostic text passes through unchanged; the tightened bearer-token pattern no longer over-redacts a bare mention of the word "bearer" in prose. |
| `codex-exec-windows-spawn.mjs` | `scripts/lib/codex-exec.mjs` | The Windows npm-shim spawning fix, added after `spawn("codex", args, { shell: false })` was found to fail `ENOENT` on win32 (no `PATHEXT` resolution for a bare command name) and a naive `shell: true` fix was found, via a live reproduction, to let cmd.exe interpret an embedded `&` in an argument as a real command separator. Ports `cross-spawn`'s escaping algorithm (fetched from its real source and cross-checked against the actual npm package on the same adversarial input) rather than reimplementing Windows `cmd.exe` escaping from scratch. Covers: `resolveWindowsExecutable`'s `PATHEXT`-based resolution (finds a `.cmd` shim on a scratch `PATH`, returns `null` for a genuinely-missing command); `escapeWindowsArgument`'s injection-resistance (no bare, un-caret-escaped metacharacter survives for a `&`/`>`-laden payload, an embedded `"` is escaped per the known algorithm shape, a plain argument round-trips predictably) and `escapeWindowsCommand`'s meta-char-only escaping; and `buildSpawnInvocation`'s three branches via its injectable `platform` param (works identically on any CI runner, not just Windows) -- non-Windows passthrough, a directly-executable `.exe` target spawned plainly, a `.cmd` shim target routed through `cmd.exe` with `windowsVerbatimArguments: true` and a caret-escaped dangerous argument, and a not-found command reporting `resolved: false` with no command/args leaking through. |
| `broker-rpc-auth.mjs` | `scripts/app-server-broker.mjs`, `scripts/lib/broker-lifecycle.mjs` | The broker's token-based RPC authentication: rejects no token, rejects a wrong token, accepts the correct token, rejects any request on a never-authenticated socket, and shuts down cleanly with the correct token. Spawns a real broker process. |
| `codex-rescue-prompt-assembly.mjs` | `skills/codex-rescue/SKILL.md`'s Phase 2 heredoc | The condensed prompt-assembly template still produces valid, parseable output; the bare-stdout `JOB_ID` capture (`--print-job-id`, no JSON parsing) still reads a representative job-file payload and its non-empty guard still fails closed on an empty one; and the `--resume-last` omission guidance stays prose-only. |
| `codex-verify-prompt-assembly.mjs` | `skills/codex-verify/SKILL.md`'s payload-assembly heredoc | The condensed `<content_trust_boundary>`/`<task>`/`<structured_output_contract>`/`<grounding_rules>`/`<completeness_contract>`/`<document>` heredoc still produces well-formed, balanced XML with the document body correctly appended; the `Assemble the blind payload` fence stays under the R18 30-line threshold; and `--persist` stays documented in `argument-hint`. |
| `codex-research-prompt-assembly.mjs` | `skills/codex-research/SKILL.md`'s payload-assembly heredoc | Same XML-balance/document-append checks as above, for research's tag set (`<content_trust_boundary>`/`<task>`/`<structured_output_contract>`/`<research_mode>`/`<citation_rules>`/`<grounding_rules>`), in both topic-only and document modes; plus the `Assemble the payload` fence staying under the R18 30-line threshold. |
| `codex-config-toml-sections.mjs` | `scripts/lib/codex-config.mjs` | The section-aware TOML read/write fix: a root-absent key never leaks a same-named key from inside a `[table]`, and writing a new root key never corrupts an existing table. Also `resolveModelAlias`'s case-insensitive lookup (`spark`/`SPARK`/`Spark` all resolve, a non-alias value passes through unchanged in its original casing). Tests the pure functions directly against in-memory strings only — never touches a real `~/.codex/config.toml`. |
| `session-lifecycle-hook.mjs` | `scripts/session-lifecycle-hook.mjs` | `handleSessionStart`'s `CLAUDE_ENV_FILE` env-var wiring (and its no-op when that env var isn't set), `cleanupSessionJobs`'s job-filtering logic (a queued/running job for the ending session is dropped, a completed job for that same session survives, a job belonging to a different session is never touched), and `handleSessionEnd`'s no-broker-session fallthrough path (completes without throwing when there's no broker session to tear down). Runs entirely under a scratch `CLAUDE_PLUGIN_DATA` directory (never a real state path); test jobs are given no `pid`, so the termination attempt `cleanupSessionJobs` makes is a real no-op, never a signal sent to an actual process. |
| `fs-atomic-write.mjs` | `scripts/lib/fs.mjs` | `writeJsonFile`'s atomic temp-file-then-rename: a successful write round-trips correctly with no leftover `.tmp-<pid>` file, a failed write (a circular-reference value that can't `JSON.stringify`) never touches the existing file's contents, and a `{ mode: 0o600 }` write actually lands with that mode on disk (POSIX only — skipped on Windows, which doesn't implement the same permission bits). Runs entirely under a scratch temp directory. |
| `codex-windows-guardrails-preflight.mjs` | `skills/codex-windows-guardrails/scripts/guarded-dispatch.mjs` | 20 scenarios in a real scratch git repo, covering both refusal and pass-through: disabled by default; an untracked local override is honored (reaches a later check, doesn't short-circuit -- deterministically stops at instruction-containment, never proceeds toward a real Codex exec); a tracked local override is ignored (fail-closed); a target outside the repository root is rejected; a nonexistent target path is rejected rather than silently dispatched against nothing; an untracked `.env` under a *directory* target is rejected (real filesystem traversal, not `git ls-files`, which would miss it); a secret file outside the declared target-paths but still under the repository root is still caught (the scan covers the whole root, matching what `danger-full-access` actually grants); an instruction file resolving inside a target path is rejected; an invalid `dispatch-id` is rejected; an uppercase `.ENV` is still caught on Windows; a `target-paths` entry with a prompt tag-closing character is rejected; a `--repo-root` that isn't the actual git toplevel is rejected; a file symlink whose real target escapes the repository root is refused outright regardless of the target's own name; a secret file reached only through an in-repo symlink is caught via the symlink's real target basename, not its own name; a directory symlink/junction escaping the repository root is refused; the same directory-escape check still fires when the symlink/junction is nested several directories deep, not just at the top level; and (source-level, since the enabled dispatch path can't be exercised without a real Codex call) `guarded-dispatch.mjs` imports `neutralizeClosingTags` and applies it to the instruction body before interpolation, includes a `<content_trust_boundary_restated>` block after it, and a controlled negative confirms these checks actually fail on a tampered copy. |
| `codex-audit-loop-invariants.mjs` | `skills/codex-audit-loop/SKILL.md` | Structural/content-invariant checks on the SKILL.md text itself (this skill has no fixed prompt template -- its output depends on 3-20 live parallel Codex calls per round against real project state): Mode A/B/C headers in order, the Mode C merge push command stays the exact non-force `git push origin <group-branch>` form, the per-group `AskUserQuestion` merge confirmation is present, Mode A's read-only/never-mutates boundary and the "never creates PRs/deploys/comments without explicit authority" boundary both hold, cost/scope confirmation is required before any mode launches, and Codex findings are documented as data to verify, never instructions. Two controlled negatives (an injected `--force` flag, a removed merge confirmation) prove the checks actually fail on a tampered copy. |
| `codex-peer-review-invariants.mjs` | `skills/codex-peer-review/SKILL.md` | Structural/content-invariant checks (no fixed prompt template -- output depends on Claude's own position and Codex's live response): Round 1/Round 2/Escalation headers in order, "Never ask before Round 1 or Round 2" is present, both command-selection literals (`review --base` for diffs, `task` for a position with no diff) are documented, the `task --resume-last` form is used for Round 2, and the subagent-dispatch and never-invent-a-tiebreak requirements hold. Two controlled negatives (removing the never-ask line, removing the subagent-dispatch requirement) prove the checks fail on a tampered copy. |
| `codex-plan-loop-invariants.mjs` | `skills/codex-plan-loop/SKILL.md` | Structural/content-invariant checks (no fixed prompt template -- each phase's payload depends on actual plan/diff content): Phase 1-6 headers in order, Phase 4's rollback-anchor (`git rev-parse HEAD`) instruction, Phase 6's `task --resume-last` form and concrete two-condition convergence exit, a persisting Critical/Major finding always being discussed with the user rather than auto-resolved, every scratch artifact staying under `${CLAUDE_PLUGIN_DATA}/codex-loop/`, and `<content_trust_boundary>` framing present in both Phase 2 and Phase 5. | `codex-prompt-protocol-references.mjs` | `skills/codex-prompt-protocol/SKILL.md` and its `references/*.md` | `disable-model-invocation: true` and the `Read`-only tool grant stay set; every reference-table row's file actually exists on disk; and a representative set of symbol names cited in `invocation-protocol.md` resolve to real functions in `codex-companion.mjs`/`scripts/lib/*.mjs`. A controlled negative (a deliberately nonexistent symbol name) proves the resolution check actually catches a broken citation. |
| `codex-session-lookup-scripts.mjs` | `skills/codex-session-lookup/scripts/find-session-id.py`, `inspect-session-file.py` | Real functional coverage of both Python scripts (a named exception to this plugin's `.mjs` convention) against scratch `history.jsonl`/rollout fixtures, never a real `~/.codex/` directory: 140-char truncation by default and `--full` suppressing it, `--last` returning the single most recent entry, malformed/incomplete JSON lines being skipped rather than crashing, `--id-only` printing only the session id, both `.json` and `.jsonl` rollout formats, and a missing/empty file producing a clear non-zero exit rather than a silent empty result. |

## When to re-run

- After any further edit to the SKILL.md/command files listed above.
- As part of `plugin-lifecycle-upstream`'s Phase 5 (Test) bounded smoke check for this plugin, or `plugin-lifecycle-downstream`'s Deep Test step for deterministic-script coverage.
- These are static/mechanical checks (bash template correctness, RPC auth logic, XML well-formedness) — they do **not** call the real Codex CLI or consume API quota, except where noted (`broker-rpc-auth.mjs` spawns a real broker process, which in turn spawns a real `codex app-server` process, but never sends it a review/task request).
