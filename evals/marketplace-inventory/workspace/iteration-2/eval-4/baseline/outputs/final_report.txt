NOTES ON THE MECHANISM

repair-history's own destructive-rewrite gate is --confirm <plugin_id> -- it must exactly
match the plugin_id argument or the command fails closed (cmd_repair_history checks this
before touching the file). The script also refuses the rewrite unless the replacement
history is structurally valid (models.validate_history_periods: exactly one open period,
last in array order, real ISO dates) and unless the replacement's open period's value
matches the record's actual current value (open_period_value vs. plugin["name"]) -- both
checks passed here since the fixture's replacement preserves demo-plugin as the final,
open-ended entry.
