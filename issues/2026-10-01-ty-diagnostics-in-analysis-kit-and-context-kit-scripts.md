# ty check reports 14 diagnostics in analysis-kit and context-kit scripts that CI never type-checks

## Summary
Running `ty check` on the plugin `scripts/` directories reports 14 diagnostics in 4 files. CI's `ty` gate covers only `scripts` and `tests`, so nobody sees them unless something type-checks the plugin sources directly.

## Environment
- **Product/Service**: `ty` type checker, run through `uv` in the repo's own environment
- **Region/Version**: `requires-python >=3.13` (`pyproject.toml`); `tool.ty.environment.extra-paths` covers the analysis-kit and session-kit scripts; repository state on 2026-10-01

## Reproduction Steps
1. Run `uv run ty check` on the `scripts/` directory of each of analysis-kit, context-kit, session-kit, workmanagement-kit, git-kit and plugin-devkit.
2. Count the reported diagnostics per file.

## Expected Behavior
Either the plugin scripts type-check cleanly, or the repo documents that they are outside the type-check gate's scope.

## Actual Behavior
14 diagnostics, all in 4 files. The other plugins' scripts report none.

| File | Count |
|---|---|
| `plugins/analysis-kit/scripts/anls_session_parser.py` | 8 |
| `plugins/analysis-kit/scripts/anls_redact_secrets.py` | 2 |
| `plugins/analysis-kit/scripts/anls_sequence_miner.py` | 2 |
| `plugins/context-kit/scripts/context-monitor.py` | 2 |

By rule: 6 `invalid-argument-type`, 6 `unresolved-attribute`, 2 `unsupported-operator`.

## Error Details
~~~
Attribute `reconfigure` is not defined on `TextIO` in union `TextIO | Any`      (anls_redact_secrets.py, lines 96-97)
Unary operator `-` is not supported for object of type `list[str] | int | Unknown`  (anls_sequence_miner.py, line 29)
Attribute `get` is not defined on `str` in union `Unknown | str`               (anls_session_parser.py, around lines 251-258)
Method `__getitem__` ... cannot be called with key of type `Literal["usage"]` on object of type `str`
                                                                               (anls_session_parser.py, around lines 253-268)
Module `ctypes` has no member `WinDLL` / `get_last_error`                       (context-monitor.py, lines 86 and 107)
~~~

## Visual Evidence
None.

## Impact
**Low** - No runtime failure is known. This is type-check hygiene in code CI does not cover.

## Additional Context
- **Why it matters now:** CI's gate is `uv run ty check scripts tests` (`.github/workflows/marketplace-ci.yml`, line 185), so plugin scripts are never type-checked there. The diagnostics surfaced only because the `commit` skill's local lint step type-checks every staged `.py`, including the generated mirror copies under `.claude/scripts/` that #446 (commit `5140d512`) newly tracks. That step was then changed (commit `6e5b0b5d`) to skip generated mirrors, so the diagnostics no longer block anything.
- **Which are real:** some look like genuine typing looseness (JSON records handled as `str`), and the two `ctypes` findings are probably false positives on a non-Windows platform (the message itself says the member may exist on other platforms). Which is which is not verified.
- **Options, not decided:** fix the annotations or add guards; add targeted ignores or `sys.platform` guards for the `ctypes` calls; or extend the documented scope of the `ty` gate.
- **If scripts are edited:** deterministic script logic needs a test (run against fixtures), and the `.claude/scripts/` mirror copies are regenerated by the post-edit hook.
- Related: #446, commit `6e5b0b5d`.
