## Summary
CI installs uv 0.12.21, while the uv pre-commit hooks run uv 0.13.7. Bump CI's pinned uv to 0.13.7 so both use the same version.

## Environment
- **Product/Service**: `.github/workflows/*` (`astral-sh/setup-uv` steps, pinned since #641), `.pre-commit-config.yaml` (`astral-sh/uv-pre-commit`)
- **Region/Version**: CI uv `0.12.21`; hook uv `0.13.7`, pinned by PR #773 (#749)
- **Browser/OS**: N/A

## Reproduction Steps
1. Read any `setup-uv` step in `.github/workflows/marketplace-ci.yml`: `version: "0.12.21"`.
2. Read `.pre-commit-config.yaml` on PR #773's branch: `astral-sh/uv-pre-commit` at `rev: 0.13.7`.

## Expected Behavior
CI and the local uv hooks run the same uv version, so a lockfile written locally is checked by the same uv in CI.

## Actual Behavior
They differ. PR #773 moved the hooks to 0.13.7 for two reasons: `[tool.uv] system-certs` needs uv 0.11 or later, and 0.13.9 was released the same day. CI stayed on 0.12.21. PR #773's advisory Claude delta review flagged the mismatch as an Informational finding.

## Error Details

None. The version difference causes no failure today (see Additional Context).
~~~

## Visual Evidence
None.

## Impact
**Low**: a consistency gap, not a failure. Before PR #773, the hooks were on uv 0.9.7 against CI's 0.12.21, so the versions already differed.

## Additional Context
Checked while preparing PR #773 with uv 0.9.7, 0.12.21, 0.13.5, 0.13.7 and 0.13.9:
- Every version accepts the current `uv.lock` (`revision = 3`).
- Re-locking with uv 0.13.x (tested with 0.13.5 and 0.13.9) writes `revision = 5`. CI's 0.12.21 reads that file (`uv lock --check` and `uv sync --locked` both pass) and doesn't write it back to 3. Local uv 0.13.x already writes revision 5 regardless of the hook version.
- uv 0.13.0's breaking changes don't affect this repo:
  - The Python 3.15 default is overridden by `.python-version` (3.13.14) and by `setup-uv`'s `python-version` input.
  - The cache format changed, but the CI cache is off.
  - Requirement-file parsing changed, but the one `requirements.txt` install uses pip.
