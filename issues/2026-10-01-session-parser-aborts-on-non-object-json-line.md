# analysis-kit: anls_session_parser aborts the whole session file on a valid-JSON line that is not an object

## Summary
`parse_session_file()` skips a broken JSON line but crashes with `AttributeError` on a line that is valid JSON and not an object (`[]`, `null`, `"x"`), so one odd line fails the parse of the entire session file.

## Environment
- **Product/Service**: analysis-kit, `plugins/analysis-kit/scripts/anls_session_parser.py`
- **Region/Version**: repository state on 2026-10-01, Python 3.13; `parse_session_file(path: Path, since: datetime | None, until: datetime | None) -> dict`

## Reproduction Steps
1. Import `anls_session_parser` from `plugins/analysis-kit/scripts/`.
2. Write a JSONL file with three lines: a valid user record, one test line from the table below, and the same valid user record again.
3. Call `parse_session_file(path, None, None)` for each test line.

## Expected Behavior
A malformed line is skipped and counted (`lines_skipped`) and the rest of the session is parsed. A line that is valid JSON but not an object is the same kind of malformed input.

## Actual Behavior
Run against the real module:

| Test line | Result |
|---|---|
| `{oops` (broken JSON) | Skipped; a `dict` is returned |
| `[]` | `AttributeError: 'list' object has no attribute 'get'` |
| `null` | `AttributeError: 'NoneType' object has no attribute 'get'` |
| `"x"` | `AttributeError: 'str' object has no attribute 'get'` |

The loop (around lines 100-111) catches only `json.JSONDecodeError`, then immediately calls `record.get("type")`. The only other `except` clauses in the file are `ValueError` (around line 64) and `(OSError, UnicodeDecodeError)` in `main()` (around line 198), so `AttributeError` is not caught anywhere on the per-file path.

## Error Details
~~~
AttributeError: 'list' object has no attribute 'get'
AttributeError: 'NoneType' object has no attribute 'get'
AttributeError: 'str' object has no attribute 'get'
~~~

## Visual Evidence
None.

## Impact
**Medium** - One odd line makes the parse fail for that whole session file. A workaround exists (remove the line).

## Additional Context
- **How it was found:** raised by the Codex pass of the cross-model review for the #446 work, then confirmed with the repro above. #446 only mirrors this file (a byte-identical copy under `.claude/scripts/`); it does not change it.
- **Related typing signal (not verified as the same cause):** `ty check` reports 8 diagnostics in this file (around lines 251-268) about JSON values being treated as `str`, which fits records, `message` and `usage` not being validated as dicts. See #453.
- **Suggested fix, not decided:** after `json.loads`, require `isinstance(record, dict)`; otherwise count it in `lines_skipped` and continue. Apply the same guard before calling `.get()` on the nested `message` and `usage` values.
- **If fixed:** it needs a regression test (deterministic script logic; a fixture JSONL with `[]`, `null` and `"x"` lines), and the `.claude/scripts/` mirror copy is regenerated by the post-edit hook.
- Related: #453, #446.
