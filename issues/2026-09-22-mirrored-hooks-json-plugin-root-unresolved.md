## Summary
`.claude/hooks/hooks.json` (the merged mirror of all registered plugins' hooks) uses `${CLAUDE_PLUGIN_ROOT}` in every entry it mirrors, which only resolves for hooks loaded from an actually-installed plugin -- never for project-level hooks. All 30 mirrored hook command entries across all 5 registered plugins (not just antigravity-kit's 4) would silently fail to resolve if this file were ever wired into live project-hook execution.

## Environment
- **Product/Service**: Claude Code plugin marketplace (`andres-cc-marketplace`), `.claude/hooks/hooks.json` (generated by `scripts/marketplace_ci/sync.py`'s `plan_hooks_merge`/`apply_hooks_merge_plan`)
- **Region/Version**: n/a (repo-wide mirror artifact)

## Reproduction Steps
1. Inspect `.claude/hooks/hooks.json`: every mirrored plugin's hook `command` field uses `${CLAUDE_PLUGIN_ROOT}` verbatim, copied byte-for-byte from each plugin's own canonical `hooks/hooks.json` (`plugins/<name>/hooks/hooks.json`) with no path substitution.
2. Per Claude Code's own official docs (`code.claude.com/docs/en/hooks`, fetched live): `${CLAUDE_PLUGIN_ROOT}` is documented as "the plugin's installation directory, for scripts bundled with a plugin" -- it is only set when a hook executes from an actually-installed plugin's own `hooks/hooks.json` manifest. Project-level hooks (defined in `.claude/settings.json`) receive `${CLAUDE_PROJECT_DIR}` instead; a standalone `.claude/hooks/hooks.json` file is not itself a documented, standard hook-registration location at all.
3. Check `.claude/settings.json` in this repo: it has no `hooks` key, so `.claude/hooks/hooks.json`'s content is not currently wired into live Claude Code hook execution through any path this repo's own settings define.

## Expected Behavior
Either (a) the merged mirror should never be treated as directly loadable/executable hook content, and that should be stated explicitly somewhere discoverable, or (b) if it's ever intended to become live-loadable (e.g. via a future `.claude/settings.json` `hooks` key referencing it), the merge process should rewrite `${CLAUDE_PLUGIN_ROOT}` to `${CLAUDE_PROJECT_DIR}/.claude` (or an equivalent project-relative form) for every mirrored entry.

## Actual Behavior
The merge (`plan_hooks_merge` in `scripts/marketplace_ci/sync.py`) does a byte-for-byte JSON merge of each plugin's own `hooks/hooks.json` content with no path rewriting at all. Right now this is dormant, not actively broken: nothing in this repo's `.claude/settings.json` or its CI/tooling actually executes `.claude/hooks/hooks.json`'s commands (confirmed by grepping `.github/` and `scripts/` for any reference that would execute it, finding none beyond `sync.py` itself, which only writes the merged JSON, never runs it). The hooks actually firing during live sessions in this repo (e.g. `guard-raw-commit.sh`, `guard-raw-pr-review.sh`) are firing from the real, separately-installed plugin copies (`plugins/<name>/hooks/hooks.json`), not from this mirror file.

## Impact
**Medium.** Not a currently-live bug -- the mirror file has no execution path today. But it's a real landmine: any future change that wires `.claude/hooks/hooks.json` into live hook execution (e.g. adding a `hooks` key to `.claude/settings.json` pointing at it, matching how the rest of the `.claude/` mirror tree is meant to give mirrored components "a shared, un-namespaced shorthand") would silently break all 30 mirrored hook entries across all 5 plugins with resolved paths like `/hooks/<script>.sh` (empty `CLAUDE_PLUGIN_ROOT`), most under `onError: warn` so the failure would be silent.

## Additional Context
Found by Codex's automated PR review of #349 (the antigravity-kit mirror-sync registration fix), scoped narrowly to antigravity-kit's own 4 mirrored hook entries. Independently investigated and found the actual scope is much larger (all 5 registered plugins, 30 entries) and the practical severity more nuanced (dormant, not live) than the original finding suggested. Same structural-mirror-limitation category as already-filed issues #345 (agent-frontmatter hooks not honored) and #350 (`bin/`-dependent mirrored commands non-functional) -- deferred here for the same reason: fixing it means redesigning `sync.py`'s hooks-merge logic (a Tier-1, review-dispatch-critical file) across all 5 plugins' worth of content, out of this PR's own scope. Suggested remediation options, none prescriptive:
1. Document explicitly (e.g. in `.claude/hooks/hooks.json`'s own generation comment, or in `AGENTS.md`) that this merged file is a reference/mirror artifact only, never meant to be directly wired into live hook execution.
2. Teach `plan_hooks_merge` to rewrite `${CLAUDE_PLUGIN_ROOT}` to a project-relative equivalent for every mirrored entry, so the file would work correctly if ever wired in.
3. Accept as a documented, permanent limitation matching this marketplace's own precedent for `bin/`-dependent commands and agent-frontmatter hooks (issues #350, #345).
